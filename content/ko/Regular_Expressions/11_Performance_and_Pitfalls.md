## 1. 정규식 엔진의 동작 원리

Python은 **NFA(비결정적 유한 오토마타)** 엔진을 사용하며, 이는 서로 다른 매칭 가능성을 시도하기 위해 **역추적**을 사용합니다:

```
NFA 엔진 과정 (간략화):

    패턴: a(b|c)*d
    입력: "abcd"

    1단계: 'a'가 'a'와 매칭 ✓
    2단계: (b|c)*가 'b' 시도 -> 'b'와 매칭 ✓
    3단계: (b|c)*가 'c' 시도 -> 'c'와 매칭 ✓
    4단계: (b|c)*가 'd' 시도 -> 'd'는 b도 c도 아님
           (b|c)* 루프 종료
    5단계: 'd'가 'd'와 매칭 ✓ -> 매칭 성공

    엔진이 옵션을 시도하고 경로가 실패하면 역추적합니다.
```

### NFA vs DFA

```
NFA (Python, Perl, Java, .NET):
    + 역참조, 탐색, 게으른 수량자 지원
    - 최악의 경우 지수적 성능 가능
    - 역추적 사용

DFA (grep, awk, 대부분의 DB 엔진):
    + 보장된 선형 시간 O(n)
    + 역추적 문제 없음
    - 역참조나 탐색 지원 불가
```

## 2. 치명적 역추적

가장 위험한 정규식 함정입니다. 특정 패턴이 **지수적** 시간 복잡도를 유발합니다:

### 전형적인 예제

```python
import re
import time

# 위험한 패턴: 중첩 수량자
pattern = r'^(a+)+$'

# 짧은 입력: 빠름
start = time.time()
re.search(pattern, "aaaaaaaaaaaaaaa!")  # 15개의 a + !
elapsed = time.time() - start
print(f"15자: {elapsed:.4f}s")

# 긴 입력은 시도하지 마세요:
# re.search(pattern, "a" * 30 + "!")  # 수 분 소요
# re.search(pattern, "a" * 40 + "!")  # 수 시간 소요
```

```
(a+)+$가 치명적 역추적을 일으키는 이유:

    입력: "aaaa!" (4개의 a + !)

    엔진이 "aaaa"를 그룹 간에 나누는 모든 방법을 시도:
    (aaaa)         -> !에서 실패
    (aaa)(a)       -> !에서 실패
    (aa)(aa)       -> !에서 실패
    (aa)(a)(a)     -> !에서 실패
    (a)(aaa)       -> !에서 실패
    (a)(aa)(a)     -> !에서 실패
    (a)(a)(aa)     -> !에서 실패
    (a)(a)(a)(a)   -> !에서 실패

    n개 문자에 대해: 2^(n-1) 가지 조합!

    n=4:    8가지 조합
    n=10:   512가지 조합
    n=20:   524,288가지 조합
    n=30:   536,870,912가지 조합 (수 분 소요)
```

### 더 많은 위험한 패턴

```
위험 (겹치는 문자에 대한 중첩 수량자):
    (a+)+          (a*)*          (a+)*
    (a|b)+         (\w+\s*)*     (.*)*

안전한 대안:
    a+             a*             a+
    [ab]+          (?:\w+\s*)*    .*

    핵심: 중복된 중첩을 제거합니다.
```

## 3. 위험한 패턴 식별

### 경험 법칙

패턴이 위험한 경우:
1. 수량자 안에 또 다른 **수량자**가 있음
2. 내부와 외부 수량자가 **같은 문자**를 매칭할 수 있음
3. 전체 매칭이 **실패**할 수 있음 (역추적을 유발)

```
패턴 분석:

    (\w+)+     위험: \w+가 ()+ 안에 -- 둘 다 단어 문자를 매칭
    (\d+\w+)+  위험: 겹침 -- \d는 \w의 부분집합
    (\d+[,-])+  안전: \d+와 [,-]가 다른 문자를 매칭
    (\w+\s)+   안전: \w+와 \s가 다른 문자를 매칭
    [^"]*      안전: 중첩 없음, 단일 수량자
```

## 4. 위험한 패턴 수정

### 전략 1: 중복 수량자 제거

```python
# 수정 전 (위험):
r'(a+)+'       # 같은 문자에 대한 중첩 수량자

# 수정 후 (안전):
r'a+'           # 동등하지만 역추적 위험 없음
```

### 전략 2: 부정 문자 클래스 사용

```python
import re

# 느림: 탐욕적 + 역추적
html = '<div class="name">value</div>'
# r'<.*>'  -- .*가 모든 것을 매칭한 후 역추적

# 빠름: 부정 문자 클래스 (역추적 불필요)
# r'<[^>]*>'  -- [^>]*가 첫 >에서 멈춤
tags = re.findall(r'<[^>]*>', html)
print(tags)  # ['<div class="name">', '</div>']
```

### 전략 3: 구체적으로 작성

```python
import re

# 느림: 모호한 패턴
pattern_slow = r'".*"'  # .*가 모든 것을 매칭한 후 역추적

# 빠름: 구체적인 패턴
pattern_fast = r'"[^"]*"'  # [^"]*가 닫는 "를 넘어갈 수 없음

# 빠른 패턴은 역추적이 불필요합니다.
# [^"]이 첫 "에서 자연스럽게 멈추기 때문입니다.
```

pattern_str = r'\b\w{3,}\b'

compiled = re.compile(pattern_str)

## 6. 문자열 메서드 vs 정규식

간단한 작업에는 문자열 메서드가 더 빠릅니다:

```
문자열 메서드를 사용하는 경우:
    ✓ 고정 텍스트 (패턴 없음)
    ✓ 단순한 포함/시작/끝 확인
    ✓ 단일 구분자로 분할
    ✓ 정확한 텍스트 치환

정규식을 사용하는 경우:
    ✓ 패턴 매칭 (가변 텍스트)
    ✓ 복잡한 분할 규칙
    ✓ 캡처 그룹 필요
    ✓ 탐색 단언
    ✓ 패턴과 함께 대소문자 무시
    ✓ 여러 대안 매칭
```

## 7. 흔한 함정

### 함정 1: `re.escape()` 잊음

```python
import re

user_search = "price (USD)"

# 잘못: 괄호가 그룹으로 해석
# 올바름: 사용자 입력 이스케이프
safe_pattern = re.escape(user_search)
match = re.search(safe_pattern, "The price (USD) is $10")
print(match.group())  # "price (USD)"
```

### 함정 2: `.`가 개행과 매칭되지 않음

```python
import re

text = "line1\nline2\nline3"

# 잘못: .가 \n과 매칭되지 않음
print(re.search(r'line1.*line3', text))  # None

# 올바름: re.DOTALL 사용
print(re.search(r'line1.*line3', text, re.DOTALL).group())
```

### 함정 3: `re.match()` vs `re.search()`

```python
import re

text = "Error: file not found"

# 잘못: match()는 시작만 확인
print(re.match(r'file', text))    # None!

# 올바름: search()는 어디서든 확인
print(re.search(r'file', text))   # Match!
```

### 함정 4: 의도하지 않은 캡처 그룹

```python
import re

# 그룹이 있는 findall은 캡처된 그룹을 반환
text = "color or colour"

# 예상 밖: 그룹 내용 반환
print(re.findall(r'colo(u?)r', text))   # ['', 'u']

# 수정: 비캡처 그룹 사용
print(re.findall(r'colou?r', text))      # ['color', 'colour']
```

## 8. 최적화 기법

### 기법 1: 패턴에 앵커 사용

```python
import re

# 앵커 없이: 엔진이 모든 위치에서 시도
re.search(r'\d{4}-\d{2}-\d{2}', "no dates here at all")
# 위치 0, 1, 2, ...에서 시도 (시간 낭비)

# 앵커 사용: 엔진이 빠르게 실패
re.search(r'^\d{4}-\d{2}-\d{2}', "no dates here at all")
# 위치 0에서만 시도, 즉시 실패
```

### 기법 2: 교대에서 빈번한 매칭을 먼저 배치

```python
import re

log = "INFO: message"  # 가장 흔한 경우

# 90%의 로그가 INFO라면 먼저 배치
pattern_optimized = r'INFO|ERROR|WARN|DEBUG'
# 엔진이 대안을 왼쪽에서 오른쪽으로 시도
# 흔한 경우를 먼저 배치하면 평균 시도 횟수 감소
```

### 기법 3: 비캡처 그룹 사용

```python
import re

# 캡처 그룹은 오버헤드가 있음 (상태 저장)
re.findall(r'(abc)+(def)+', text)       # 캡처 (느림)
re.findall(r'(?:abc)+(?:def)+', text)   # 비캡처 (빠름)
```

## 9. 모범 사례 요약

```
해야 할 것:
    ✓ 원시 문자열 (r"") 사용
    ✓ 반복 사용하는 패턴은 컴파일
    ✓ 캡처가 불필요하면 비캡처 그룹 (?:...) 사용
    ✓ 게으른 .*? 대신 문자 클래스 [^X] 사용
    ✓ 가능하면 패턴에 앵커 (^, $, \b) 사용
    ✓ 복잡한 패턴에 re.VERBOSE 사용
    ✓ 매칭과 비매칭 입력 모두로 테스트
    ✓ 사용자 입력에 re.escape() 사용

하지 말아야 할 것:
    ✗ 겹치는 패턴에 수량자 중첩: (a+)+
    ✗ HTML, JSON, XML 파싱에 정규식 사용
    ✗ 문자열 메서드로 충분한 경우 정규식 사용
    ✗ 엣지 케이스 테스트를 잊음 (빈 문자열, 매우 긴 입력)
    ✗ 더 구체적인 패턴이 가능한 곳에 .* 사용
    ✗ 역추적 동작 무시
```

## 요약

| 주제 | 핵심 내용 |
|------|----------|
| 치명적 역추적 | 겹치는 문자에 대한 중첩 수량자 = 지수적 시간 |
| 예방 | 게으른 `.*?` 대신 부정 클래스 `[^X]*` 사용 |
| `re.compile()` | 미세한 속도 향상; 주로 가독성과 재사용을 위해 |
| 문자열 메서드 | 단순한 고정 텍스트 작업에 더 빠름 |
| 앵커 | `^`, `$`, `\b`가 엔진의 빠른 실패에 도움 |
| 테스트 | 실패하는 입력으로 항상 테스트 (NFA의 최악 케이스) |
