## 1. CPU vs GPU: 설계 철학의 대비

CPU와 GPU는 근본적으로 서로 다른 문제를 해결합니다:

| 측면 | CPU | GPU |
|------|-----|-----|
| **코어 수** | 4–128 | 1,000–18,000+ |
| **클록 속도** | 3–5 GHz | 1–2 GHz |
| **코어당 캐시** | 큼 (코어당 MB 단위) | 작음 (SM 간 공유) |
| **최적화 목표** | 단일 스레드 **지연(latency) 최소화** | 수천 스레드의 **처리량(throughput) 최대화** |
| **분기 예측** | 공격적 (>15단계 파이프라인) | 단순 (분기 발산은 처리량 저하) |
| **SIMD 폭** | 8–16 FP32 (AVX-512) | warp당 32 FP32, SM당 128 warp |
| **메모리 모델** | 일관성 있는 균일 지연 | 고대역폭, 고지연 DRAM |

**핵심 통찰**: GPU는 단일 스레드 성능을 **대규모 병렬 처리량**과 맞바꿉니다. 32개 스레드로 구성된 하나의 warp가 같은 명령을 동시에 실행합니다. 한 warp가 메모리를 기다리는 동안 다른 warp가 실행됩니다 — 이것이 **병렬성을 통한 지연 은폐(latency hiding)**입니다.

## 2. GPU 하드웨어 계층 구조

### 스트리밍 멀티프로세서 (SM)

SM은 GPU의 기본 연산 단위로, CPU 코어와 유사하지만 훨씬 특화되어 있습니다:

```
┌─────────────────────────────────────────────────────┐
│                  스트리밍 멀티프로세서 (SM)            │
│                                                       │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐  │
│  │  Warp 0  │ │  Warp 1  │ │  Warp 2  │ │  ...   │  │
│  │ 32 스레드 │ │ 32 스레드 │ │ 32 스레드 │ │        │  │
│  └──────────┘ └──────────┘ └──────────┘ └────────┘  │
│                    │                                  │
│  ┌─────────────────▼──────────────────────────────┐  │
│  │              Warp 스케줄러                       │  │
│  │    (매 사이클마다 준비된 warp 선택)               │  │
│  └─────────────────────────────────────────────────┘  │
│                    │                                  │
│  ┌─────────────────▼──────────────────────────────┐  │
│  │  INT32/FP32 ALU  │  FP64 ALU  │  텐서 코어      │  │
│  └─────────────────────────────────────────────────┘  │
│                                                       │
│  ┌─────────────────────────────────────────────────┐  │
│  │      공유 메모리 / L1 캐시 (48–228 KB)           │  │
│  └─────────────────────────────────────────────────┘  │
│                                                       │
│  ┌─────────────────────────────────────────────────┐  │
│  │   레지스터 파일 (64K × 32비트 레지스터)           │  │
│  └─────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

**NVIDIA A100 GPU:**
- SM 108개
- SM당 FP32 CUDA 코어 64개 → **총 6,912개 CUDA 코어**
- SM당 32 warp → 동시 활성 3,456 warp
- 40–80 GB HBM2e 메모리, **2 TB/s** 대역폭
- **312 TFLOPS** FP16 텐서 코어, **77 TFLOPS** FP32

### 메모리 계층 구조

```
레지스터     ←→  L1 / 공유    ←→  L2 캐시     ←→  HBM / GDDR
~0 사이클        1–5 사이클      50–100 사이클    400–700 사이클
256 KB/SM        48–228 KB/SM    40–80 MB         총 40–80 GB
~19 TB/s         ~19 TB/s        ~5 TB/s          ~2 TB/s (A100)
```

## 3. Warp: GPU 실행 단위

**warp**는 SIMT(Single Instruction, Multiple Threads) 방식으로 같은 명령을 동시에 실행하는 **32개 스레드** 그룹입니다.

### SIMT vs SIMD

```
SIMD (CPU, AVX2):   명령 1개, 부동소수점 8개, 같은 데이터 벡터
SIMT (GPU, warp):   명령 1개, 스레드 32개, 각자 다른 데이터
```

SIMT에서 warp의 각 스레드는:
- 자신만의 **레지스터** (비공개)
- 자신만의 **프로그램 카운터** (발산 없을 때 블록 내 모든 warp가 같은 PC 공유)
- **공유 메모리** (블록 단위)와 **전역 메모리** (장치 단위)에 접근 가능

### Warp 스케줄링과 지연 은폐

SM은 많은 warp를 동시에 상주시킵니다. 한 warp가 메모리 접근(400+ 사이클 지연)으로 정지하면, warp 스케줄러가 **즉시 다른 준비된 warp로 전환**합니다:

```
사이클: 0   400   800   1200
Warp 0: LOAD  ....  COMPUTE  STORE
Warp 1:      LOAD  ....  COMPUTE
Warp 2:           LOAD  ....  COMPUTE
Warp 3:                LOAD  ...
                                ↑
                     유휴 사이클 없음 — 지연이 숨겨짐
```

이것이 GPU가 높은 메모리 지연을 견디는 핵심 이유입니다: **점유율(occupancy)**(활성 warp 대 최대 가능 warp의 비율)이 지연 은폐 효과를 결정합니다.

## 4. 점유율 (Occupancy)

**점유율** = SM당 활성 warp / SM당 최대 warp

A100의 SM당 최대 warp: 64

점유율 제한 요인:
1. **레지스터 사용량**: 스레드당 레지스터가 많을수록 → 수용 스레드 수 감소 → 점유율 저하
2. **공유 메모리**: 블록당 공유 메모리가 많을수록 → 블록 수 감소 → warp 감소
3. **블록 크기**: 반드시 32의 배수여야 함; 매우 작은 블록은 잠재적 점유율 낭비

```
예시: 커널이 스레드당 레지스터 32개, 블록 크기 = 128 (4 warp) 사용
  레지스터 한도: 256KB / (32 레지스터 × 4바이트 × 32 스레드) = 64 warp ✓
  SM당 최대 블록 = 64 warp / 블록당 4 warp = 16 블록
  점유율 = 64/64 = 100%

커널이 스레드당 레지스터 64개를 사용한다면:
  레지스터 한도: 256KB / (64 × 4 × 32) = 32 warp
  점유율 = 32/64 = 50%
```

> **높은 점유율이 보통 더 좋지만** 항상 그런 것은 아닙니다 — SM당 스레드가 적지만 스레드당 레지스터가 더 많은 커널이 더 나은 처리량을 달성하기도 합니다.

## 5. GPU 메모리 대역폭: 실제 병목

대부분의 커널에서 **메모리 대역폭이 제한 요인**이며, 연산 능력이 아닙니다.

```
A100 이론치:
  최대 FP32:        19.5 TFLOPS
  메모리 대역폭: 2.0 TB/s

대역폭-연산 비율: 2.0e12 / 19.5e12 = 바이트당 0.103 FLOP
연산 병목이 되려면 필요한 산술 강도: > 9.8 FLOP/바이트

벡터 덧셈 (y = a*x + b):
  FLOP = 2N (곱셈 1, 덧셈 1)
  바이트 = 3N × 4 (x 읽기, y 읽기, y 쓰기)
  AI = 2N / 12N = 0.17 FLOP/바이트 → 메모리 병목 (임계값의 58분의 1)

행렬 곱셈 (C = A × B, NxN):
  FLOP = 2N^3
  바이트 = 3N^2 × 4 (A, B 읽기; C 쓰기) [재사용 무시]
  AI = 2N^3 / 12N^2 = N/6
  N=1024: AI = 170 FLOP/바이트 → 연산 병목 ✓
```

이것이 **루프라인 모델**입니다 — L10에서 실제 커널 분석에 활용합니다.

## 6. GPU 세대 비교

| GPU | 아키텍처 | SM | FP32 TFLOPS | BW (TB/s) | 텐서 (FP16) |
|-----|---------|-----|-------------|-----------|------------|
| RTX 3090 | Ampere | 82 | 35.6 | 0.94 | 285 TFLOPS |
| A100 (80GB) | Ampere | 108 | 19.5 | 2.0 | 312 TFLOPS |
| RTX 4090 | Ada | 128 | 82.6 | 1.01 | 660 TFLOPS |
| H100 SXM | Hopper | 132 | 67.0 | 3.35 | 1979 TFLOPS (FP8) |
| L40S | Ada | 142 | 91.6 | 0.86 | 733 TFLOPS |

**핵심 관찰**:
- H100은 A100보다 **메모리 대역폭이 67% 높음** — 메모리 병목 커널에 결정적
- RTX 4090은 A100의 4배 FP32 TFLOPS지만 메모리 대역폭은 절반 — 연산 병목에 유리, 메모리 병목에는 불리
- 텐서 코어 (FP16/BF16)는 CUDA 코어보다 4–16배 빠름 — DL 학습에서 핵심적으로 활용

## 7. 이론적 성능 계산

### 커널의 기계 균형 계산:

```python
# 예시: A100 GPU
compute_tflops = 19.5    # FP32 TFLOPS
bandwidth_tbps = 2.0     # TB/s

# 기계 능선점 (연산 = 메모리인 bytes/FLOP)
ridge = compute_tflops / bandwidth_tbps  # = 9.75 FLOP/바이트

# AI = 5 FLOP/바이트인 커널은 메모리 병목:
#   달성 가능한 최대 처리량 = 5 * 2.0 TB/s = 10 TFLOPS  (19.5가 아님)
```

### 실행 시간 추정:

```python
N = 1024  # 행렬 차원 (N×N 행렬 곱)
flops = 2 * N**3        # = 21억 FLOP
bytes = 3 * N**2 * 4    # = 12.6 MB (A, B 읽기, C 쓰기)
ai    = flops / bytes   # = 167 FLOP/바이트 (강한 연산 병목)

# 연산 병목:
time_compute = flops / (19.5e12)   # = 0.11 ms
# 메모리 병목:
time_memory  = bytes / (2.0e12)    # = 0.006 ms

actual_time = max(time_compute, time_memory)  # = 0.11 ms (연산 병목)
```

## 8. 실습: GPU 정보 조회

```c
// gpu_info.cu
#include <stdio.h>
#include <cuda_runtime.h>

int main(void) {
    int device_count;
    cudaGetDeviceCount(&device_count);
    printf("발견된 CUDA 장치: %d\n", device_count);

    for (int i = 0; i < device_count; i++) {
        struct cudaDeviceProp prop;
        cudaGetDeviceProperties(&prop, i);

        printf("\n장치 %d: %s\n", i, prop.name);
        printf("  연산 능력:          %d.%d\n",
               prop.major, prop.minor);
        printf("  SM 수:              %d\n",
               prop.multiProcessorCount);
        printf("  Warp 크기:          %d 스레드\n",
               prop.warpSize);
        printf("  SM당 최대 스레드:   %d\n",
               prop.maxThreadsPerMultiProcessor);
        printf("  SM당 최대 warp:     %d\n",
               prop.maxThreadsPerMultiProcessor / prop.warpSize);
        printf("  전역 메모리:        %.1f GB\n",
               (float)prop.totalGlobalMem / 1e9);
        printf("  메모리 대역폭:      %.1f GB/s\n",
               2.0 * prop.memoryClockRate * (prop.memoryBusWidth / 8) / 1e6);
        printf("  L2 캐시:            %d MB\n",
               prop.l2CacheSize / (1024*1024));
        printf("  SM당 공유 메모리:   %zu KB\n",
               prop.sharedMemPerMultiprocessor / 1024);
        printf("  SM당 레지스터:      %d\n",
               prop.regsPerMultiprocessor);
    }
    return 0;
}
```

```bash
nvcc -o gpu_info gpu_info.cu && ./gpu_info
```

## 핵심 요약

- GPU는 수천 개의 단순한 코어 vs 수십 개의 복잡한 코어: **처리량** 최적화, 단일 스레드 지연이 아님
- **warp** (32 스레드)는 원자적 실행 단위 — 32개 스레드 모두 같은 명령 실행
- **점유율** = 활성 warp / 최대 warp; 높은 점유율은 스레드 전환을 통해 메모리 지연 은폐
- **메모리 대역폭** (연산이 아님)이 대부분의 커널에서 병목 — 커널의 산술 강도를 이해해야 함
- 루프라인 모델은 커널이 메모리 병목인지 연산 병목인지 예측하고 성능 기대치를 설정해줌
