## 1. 핵심 질문

**왜 그냥 커널을 실행해서 보면 안 되나요?**

성능 모델 없이는 커널이 느린 이유가 다음 중 무엇인지 알 수 없습니다:
- (a) 메모리 대역폭 제한 → 메모리 접근 최적화
- (b) 연산 제한 → 벡터화, 언롤, 텐서 코어 사용
- (c) 이미 최대 성능 달성 → 최적화 중단

**루프라인 모델**은 최적화를 시작하기 전에 이를 답해줍니다.

## 2. 산술 강도

**산술 강도(AI)** = FLOP / 메모리 트래픽 바이트

```
AI = (부동소수점 연산 수) / (전역 메모리에서 읽은 + 쓴 바이트 수)
```

이것은 하드웨어가 아닌 **알고리즘**의 특성입니다.

### 예시

**벡터 덧셈** (`c[i] = a[i] + b[i]`):
```
FLOP = 원소당 덧셈 1개 = N FLOP
바이트 = 3N × 4 (a 읽기, b 읽기, c 쓰기)
AI = N / (12N) = 1/12 ≈ 0.083 FLOP/바이트
```

**내적** (`sum += a[i] * b[i]`):
```
FLOP = 2N (곱셈 + 누적)
바이트 = 2N × 4 (a, b 읽기; 리덕션 결과 쓰기는 원소당 계산 안 함)
AI = 2N / 8N = 0.25 FLOP/바이트
```

**행렬 곱셈** (`C = A × B`, N×N):
```
FLOP = 2N³ (N³ 곱셈 + N³ 덧셈)
바이트 = (N² + N² + N²) × 4 = 12N² 바이트 (A, B 읽기; C 쓰기)
AI = 2N³ / 12N² = N/6 FLOP/바이트

N=1024: AI = 170 FLOP/바이트  (강한 연산 병목)
N=64:   AI = 10.7 FLOP/바이트 (경계)
N=16:   AI = 2.7  FLOP/바이트 (소형 크기에서 메모리 병목)
```

**스텐실** (7점 3D, `u[i] = a*u[i-1] + b*u[i] + a*u[i+1] + ...`):
```
FLOP = 13N (덧셈 6, 곱셈 6, 스케일 1)
바이트 ≈ 7N × 4 (읽기 7, 이웃이 재사용되면 쓰기 ~1)
AI = 13N / 28N ≈ 0.46 FLOP/바이트  (메모리 병목)
```

## 3. 루프라인 차트

루프라인 차트는 두 개의 축을 가집니다:
- x축: 산술 강도 (FLOP/바이트, 로그 눈금)
- y축: 성능 (GFLOPS, 로그 눈금)

두 개의 "지붕":
1. **메모리 대역폭 지붕**: `성능 = AI × 대역폭` (대각선)
2. **연산 지붕**: `성능 = 최대_FLOPS` (수평선)

```
GFLOPS
  │
  │ 연산 지붕 (A100 FP32: 19,500 GFLOPS)
  │─────────────────────────────────────────────────────────
  │                              / ← 능선점 (9.75 FLOP/바이트)
  │                             /
  │                            /   ← 루프라인 (2.0 TB/s 기울기)
  │                           /
  │                          /      ●  GEMM (170 FLOP/바이트) → 연산 지붕 근처
  │                         /
  │                        /     ● 스텐실 (0.46 FLOP/바이트) → 메모리 병목
  │                       /
  │         ● 벡터 덧셈 (0.083)
  │                      /
  └────────────────────────────────────────────────────────── AI (FLOP/바이트)
   0.01   0.1    1    10   100  1000
```

**능선점(ridge point)**은 메모리 대역폭 선이 연산 지붕을 만나는 지점입니다:
```
능선점 = 최대_FLOPS / 대역폭 = 19,500 GFLOPS / 2,000 GB/s = 9.75 FLOP/바이트 (A100 FP32)
```

AI < 능선점인 모든 커널은 메모리 병목입니다. AI > 능선점은 연산 병목입니다.

## 4. 아키텍처별 GPU 능선점

```python
# 능선점 = 최대_FLOPS / 대역폭 (단위: FLOP/바이트)
gpus = {
    "A100 (FP32)":   19_500 / 2_000,   # = 9.75  FLOP/바이트
    "A100 (FP16)":  312_000 / 2_000,   # = 156   FLOP/바이트 (텐서 코어)
    "H100 (FP32)":   67_000 / 3_350,   # = 20.0  FLOP/바이트
    "H100 (FP8)":  1_979_000 / 3_350,  # = 590   FLOP/바이트 (텐서 코어)
    "RTX 4090 (FP32)": 82_600 / 1_008, # = 81.9  FLOP/바이트
    "RTX 3090 (FP32)": 35_600 /   936, # = 38.0  FLOP/바이트
}
```

**핵심 통찰**: H100의 텐서 코어 능선점은 590 FLOP/바이트입니다 — 대규모 데이터 재사용을 가진 FlashAttention 스타일의 커널만이 텐서 코어에서 연산 병목이 될 수 있습니다.

## 5. 커널에 대한 루프라인 구성

1단계: FLOP 수를 측정하거나 계산합니다.
2단계: 실제 읽기/쓰기 바이트를 측정합니다 (`ncu` 메트릭 사용 또는 분석적으로 계산).
3단계: AI = FLOP / 바이트 계산합니다.
4단계: AI를 능선점과 비교 → 병목 결정합니다.
5단계: 달성 가능한 최대 성능 계산 = `min(AI × BW, 최대_FLOPS)`.

### 예시: 벡터 스케일 (`y[i] = alpha * x[i]`)

```python
N = 1e6  # 100만 개 원소

# 분석적:
FLOP  = 1 * N         # 원소당 곱셈 1개
바이트 = 2 * N * 4    # x 읽기, y 쓰기 (원소당 8바이트)
AI    = FLOP / 바이트  # = 1 / 8 = 0.125 FLOP/바이트

# A100 FP32 능선점 = 9.75 FLOP/바이트 → 메모리 병목
달성가능_GFLOPS = min(AI * 2000, 19500)  # = 0.125 * 2000 = 250 GFLOPS
달성가능_시간   = FLOP / (달성가능_GFLOPS * 1e9)  # = 4 μs

# 측정값: 4.2 μs → 238 GFLOPS → 루프라인의 95% → 우수!
```

## 7. 루프라인 스크립트

```python
import numpy as np
import matplotlib.pyplot as plt

def roofline_plot(peak_gflops, peak_bw_gbs, kernels):
    """
    peak_gflops: GFLOPS의 연산 상한
    peak_bw_gbs: GB/s의 메모리 대역폭
    kernels: (이름, ai, 달성_gflops) 목록
    """
    ridge = peak_gflops / peak_bw_gbs

    ai_range = np.logspace(-2, 4, 500)
    bw_line  = peak_bw_gbs * ai_range
    roof     = np.minimum(bw_line, peak_gflops)

    plt.figure(figsize=(10, 6))
    plt.loglog(ai_range, roof, 'b-', linewidth=2, label='루프라인')
    plt.axvline(ridge, color='gray', linestyle='--', alpha=0.5)
    plt.text(ridge * 1.1, peak_gflops * 0.5, f'능선점: {ridge:.1f}', color='gray')

    for name, ai, perf in kernels:
        efficiency = perf / min(ai * peak_bw_gbs, peak_gflops)
        plt.scatter(ai, perf, s=100, zorder=5)
        plt.annotate(f'{name}\n({efficiency:.0%})', (ai, perf),
                     textcoords='offset points', xytext=(5, 5))

    plt.xlabel('산술 강도 (FLOP/바이트)')
    plt.ylabel('성능 (GFLOPS)')
    plt.title('루프라인 모델 — NVIDIA A100')
    plt.grid(True, which='both', alpha=0.3)
    plt.legend()
    plt.savefig('roofline.png', dpi=150, bbox_inches='tight')

# A100 예시
roofline_plot(
    peak_gflops = 19_500,
    peak_bw_gbs = 2_000,
    kernels = [
        ("vec_add",   0.083, 150),      # 메모리 병목, 루프라인 근처
        ("gemm1024",  170,   17_000),   # 연산 병목, 루프라인 근처
        ("stencil",   0.46,  800),      # 메모리 병목, 개선 여지 있음
    ]
)
```

## 8. 루프라인을 이용한 최적화 안내

커널이 **루프라인 아래**에 있다면:
- 메모리 지붕 아래의 메모리 병목 커널 → 합치기 개선, 스트라이드 접근 감소, 공유 메모리 사용, 중복 로드 감소
- 연산 지붕 아래의 연산 병목 커널 → 산술 중복 감소, `float4`로 벡터화, 텐서 코어 사용, 루프 언롤

커널이 **루프라인 위에** 있다면:
- 메모리 병목이고 메모리 지붕에 있음 → 대역폭 한도에 도달; 순수 소프트웨어 최적화는 도움이 안 됨
- 연산 병목이고 연산 지붕에 있음 → 이론적 최대에 도달; 알고리즘 변경 (타일링을 통한 AI 감소) 또는 더 나은 하드웨어 필요

---

## 핵심 요약

- **산술 강도(AI)** = FLOP / 바이트 — 하드웨어와 무관한 알고리즘의 특성
- **능선점** = 최대_FLOPS / 대역폭 — 능선점 위의 AI는 연산 병목, 아래는 메모리 병목
- **달성 가능한 성능** = `min(AI × 대역폭, 최대_FLOPS)` — 어떤 커널에 대한 하드 상한
- 대부분의 BLAS-1/2, 스텐실, 소프트맥스 연산은 현대 GPU에서 메모리 병목
- GEMM (대형 N)과 FlashAttention (타일링 포함)은 연산 병목
- 루프라인은 최적화된 코드를 한 줄도 작성하기 전에 어디에 최적화 노력을 써야 하는지 알려줍니다
