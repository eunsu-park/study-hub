## 객체 지향 프로그래밍이란?

객체 지향 프로그래밍(OOP)은 소프트웨어를 함수와 순차 로직이 아닌 **객체** — 관련된 데이터와 동작의 묶음 — 중심으로 조직하는 **프로그래밍 패러다임**입니다. 컴퓨터가 따라야 할 명령 목록을 작성하는 대신, OOP는 이렇게 묻습니다: "내 시스템의 *사물*은 무엇이고, 어떻게 상호작용하는가?"

```

│   - 속도           - 배터리       - 잔액             │
```

핵심 통찰은 OOP가 인간이 세계를 자연스럽게 인식하는 방식 — 각각 속성(데이터)과 능력(동작)을 가진 별개의 엔티티들의 모음 — 을 반영한다는 것입니다.

## 절차적 프로그래밍 vs 객체 지향 프로그래밍

### 절차적 접근법

절차적 프로그래밍에서는 데이터를 조작하는 **프로시저**(함수) 중심으로 코드를 구성합니다. 데이터와 함수는 분리되어 있습니다.

```python
# 절차적 접근법: 은행 계좌
account_owner = "Alice"
account_balance = 1000.0

def deposit(balance, amount):
    if amount <= 0:
        raise ValueError("금액은 양수여야 합니다")
    return balance + amount

def withdraw(balance, amount):
    if amount > balance:
        raise ValueError("잔액이 부족합니다")
    return balance - amount

# 사용법: 데이터를 명시적으로 전달해야 함
account_balance = deposit(account_balance, 500)
account_balance = withdraw(account_balance, 200)
```

이 접근법의 문제점:
- **데이터와 함수가 분리됨**: `account_balance`와 `deposit()`를 연결하는 것이 없음
- **보호 없음**: 어떤 코드든 `account_balance`를 직접 수정 가능
- **확장 문제**: 수백 개의 계좌를 관리할 때 별도 변수 관리가 복잡해짐
- **구조 없음**: 데이터 요소 간의 관계가 암묵적임

### 객체 지향 접근법

OOP에서는 데이터와 그것을 조작하는 함수가 객체 안에 **함께 묶여** 있습니다.

```python
# 객체 지향 접근법
class BankAccount:
    def __init__(self, owner, balance=0.0):
        self.owner = owner
        self._balance = balance  # 언더스코어 = "직접 건드리지 마세요"

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("금액은 양수여야 합니다")
        self._balance += amount

    def withdraw(self, amount):
        if amount > self._balance:
            raise ValueError("잔액이 부족합니다")
        self._balance -= amount

    @property
    def balance(self):
        return self._balance

# 사용법: 데이터와 동작이 함께 존재
alice = BankAccount("Alice", 1000.0)
alice.deposit(500)
alice.withdraw(200)
print(alice.balance)  # 1300.0
```

## OOP의 간략한 역사

### 타임라인

```
1960s ──── 1970s ──── 1980s ──── 1990s ──── 2000s ──── 2010s+
  │          │          │          │          │          │
Simula    Smalltalk   C++       Java       C#       Rust/Go
(1967)    (1972)     (1979)    (1995)     (2000)   (트레이트,
 │         │          │         │          │       인터페이스)
 │         │          │         │          │
 ▼         ▼          ▼         ▼          ▼
최초의    순수 OOP   OOP +    엔터프라이즈 현대 OOP
클래스    "모든 것이  절차적    OOP        + 다른
& 객체    객체"      하이브리드            패러다임
```

- **1967 — Simula**: 클래스, 객체, 상속, 가상 메서드를 도입. OOP의 "할아버지"
- **1972 — Smalltalk** (Alan Kay, Xerox PARC): 가장 순수한 OOP 언어 — 숫자와 불리언까지 모든 것이 객체
- **1979 — C++** (Bjarne Stroustrup): C에 클래스를 추가하여 시스템 프로그래밍에 OOP를 도입
- **1995 — Java**: 엔터프라이즈에서 OOP를 주류로 만듦. "한 번 작성하면 어디서든 실행"
- **2000년대 — C#, Ruby, Python**: 깔끔한 구문, 동적 타이핑, 다중 패러다임 지원으로 OOP를 개선
- **2010년대+ — 현대 언어**: Rust (트레이트), Go (상속 없는 인터페이스), Kotlin (데이터 클래스)

### Alan Kay의 원래 비전

"객체 지향 프로그래밍"이라는 용어를 만든 Alan Kay는 이렇게 설명했습니다:

> "객체가 생물학적 세포처럼... 메시지로 소통할 수 있다고 생각했습니다."

그의 비전은 상속 계층 구조가 아닌 자율적인 객체 간의 **메시지 전달**에 관한 것이었습니다.

## OOP의 네 가지 기둥

```
┌─────────────────────────────────────────────────┐
│              OOP의 네 가지 기둥                  │
├────────────┬───────────┬───────────┬────────────┤
│            │           │           │            │
│ 캡슐화     │ 상속      │ 다형성    │ 추상화     │
│            │           │           │            │
│ 데이터 +   │ 기존      │ 같은      │ 복잡성을   │
│ 메서드를   │ 클래스    │ 인터페이스│ 단순한     │
│ 묶고,      │ 에서 새   │ 다른 동작 │ 인터페이스 │
│ 내부를     │ 클래스    │           │ 뒤에 숨김  │
│ 숨김       │ 생성      │           │            │
│            │           │           │            │
│ 레슨 04    │ 레슨 05   │ 레슨 07   │ 레슨 08    │
└────────────┴───────────┴───────────┴────────────┘
```

1. **캡슐화**: 데이터와 그 데이터를 조작하는 메서드를 함께 묶으면서 일부 구성 요소에 대한 직접 접근을 제한합니다.

2. **상속**: 기존 클래스를 기반으로 새 클래스를 생성하여 속성과 메서드를 물려받습니다.

3. **다형성**: 서로 다른 타입의 객체를 같은 인터페이스를 통해 사용할 수 있습니다.

4. **추상화**: 복잡한 구현 세부사항을 단순한 인터페이스 뒤에 숨깁니다.

## 왜 OOP인가?

### 장점

- **모듈성**: 코드가 독립적으로 개발하고 테스트할 수 있는 자기 완결적 객체로 구성됨
- **재사용성**: 클래스를 프로젝트 간에 재사용할 수 있으며, 상속으로 기존 코드 확장 가능
- **유지보수성**: 한 객체의 변경이 전체 코드에 파급되지 않음
- **모델링**: OOP는 현실 세계의 엔티티에 자연스럽게 매핑되어 설계가 직관적
- **협업**: 팀이 명확한 인터페이스로 서로 다른 클래스를 동시에 작업 가능

### OOP가 빛나는 경우

- 상호작용하는 많은 엔티티가 있는 복잡한 시스템 (예: 게임, GUI, 기업 앱)
- 현실 세계의 관계를 모델링해야 하는 시스템
- 시간이 지남에 따라 성장하고 발전할 코드베이스
- 팀 간 코드 재사용이 필요한 프로젝트

### OOP가 과한 경우

- 단순한 스크립트와 일회성 데이터 변환
- 순수 수학적 계산 (함수형 프로그래밍이 더 나을 수 있음)
- 성능이 중요한 내부 루프 (OOP 오버헤드가 문제될 수 있음)
- 100줄 미만의 소규모 프로그램

## 첫 번째 클래스 작성하기

개념을 확실히 하기 위해 완전한 클래스를 작성해 봅시다:

```python
class Dog:
    """간단한 Dog 클래스로 OOP 기초를 보여줍니다."""

    # 클래스 속성: 모든 인스턴스가 공유
    species = "Canis familiaris"

    def __init__(self, name, age, breed):
        """새로운 Dog 인스턴스를 초기화합니다."""
        self.name = name      # 인스턴스 속성
        self.age = age         # 인스턴스 속성
        self.breed = breed     # 인스턴스 속성

    def bark(self):
        """개가 짖습니다."""
        return f"{self.name} says: Woof!"

    def describe(self):
        """개에 대한 설명을 반환합니다."""
        return f"{self.name} is a {self.age}-year-old {self.breed}"

    def birthday(self):
        """개의 생일을 축하합니다."""
        self.age += 1
        return f"Happy birthday, {self.name}! Now {self.age} years old."


# 인스턴스(객체) 생성
rex = Dog("Rex", 3, "German Shepherd")
bella = Dog("Bella", 5, "Golden Retriever")

# 메서드 사용
print(rex.bark())        # Rex says: Woof!
print(bella.describe())  # Bella is a 5-year-old Golden Retriever
print(rex.birthday())    # Happy birthday, Rex! Now 4 years old.
```

### 클래스의 구조

```
class Dog:                          <-- 클래스 정의
    species = "Canis familiaris"    <-- 클래스 속성 (공유)

    def __init__(self, name, age):  <-- 생성자 (초기화 메서드)
        self.name = name            <-- 인스턴스 속성
        self.age = age              <-- 인스턴스 속성

    def bark(self):                 <-- 인스턴스 메서드
        return f"{self.name}: Woof!"

rex = Dog("Rex", 3)                <-- 인스턴스화 (객체 생성)
rex.bark()                          <-- 메서드 호출 (메시지 전달)
```

## 핵심 용어

| 용어 | 정의 |
|------|------|
| **클래스 (Class)** | 객체를 만들기 위한 청사진/템플릿 |
| **객체 (Object)** | 클래스의 인스턴스; 구체적인 엔티티 |
| **인스턴스 (Instance)** | 객체의 동의어; "클래스에서 생성됨"을 강조 |
| **속성 (Attribute)** | 객체에 저장된 데이터 ("필드" 또는 "프로퍼티"라고도 함) |
| **메서드 (Method)** | 클래스 내부에 정의되어 인스턴스를 조작하는 함수 |
| **생성자 (Constructor)** | 객체 생성 시 호출되는 특수 메서드 (Python에서는 `__init__`) |
| **인스턴스화 (Instantiation)** | 클래스에서 객체를 생성하는 과정 |
| **메시지 전달 (Message passing)** | 객체의 메서드를 호출하는 것 (객체에 "메시지"를 보냄) |
| **상태 (State)** | 객체의 속성들의 현재 값 |
| **동작 (Behavior)** | 객체가 할 수 있는 것, 메서드로 정의됨 |

## 요약

- OOP는 데이터와 동작을 결합한 **객체** 중심으로 코드를 구성합니다
- 절차적 프로그래밍과 비교하여 OOP는 더 나은 모듈성, 캡슐화, 코드 재사용을 제공합니다
- OOP는 Simula(1967)에서 Smalltalk, C++, Java를 거쳐 현대 다중 패러다임 언어로 발전했습니다
- 네 가지 기둥 — 캡슐화, 상속, 다형성, 추상화 — 이 토대를 형성합니다
- OOP는 복잡하고 진화하는 시스템에 이상적이지만 단순한 스크립트에는 과할 수 있습니다
- Python에서는 `class`로 클래스를 정의하고, `__init__`으로 초기화하며, 클래스를 호출하여 객체를 생성합니다
