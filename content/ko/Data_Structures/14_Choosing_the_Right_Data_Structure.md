# 올바른 자료구조 선택

**이전**: [탐색 기초](./13_Searching_Fundamentals.md)

## 학습 목표

이 레슨을 완료하면 다음을 할 수 있습니다:

1. 여러 차원에서 자료구조를 비교할 수 있다 (시간, 공간, 사용 사례)
2. 올바른 자료구조를 선택하기 위한 체계적인 의사결정 프레임워크를 적용할 수 있다
3. 일반적인 문제 패턴과 최적의 자료구조를 식별할 수 있다
4. 자료구조 선택에서 시간-공간 트레이드오프를 이해할 수 있다
5. 자료구조 선택의 흔한 실수를 피할 수 있다
6. 실제 문제를 적절한 자료구조에 매핑할 수 있다
7. 복잡한 요구사항을 위해 여러 자료구조를 결합할 수 있다

---

올바른 자료구조를 선택하는 것은 소프트웨어 엔지니어링에서 가장 영향력 있는 결정 중 하나입니다. 잘못된 선택은 O(n) 연산을 O(n^2)으로 바꾸거나 메가바이트의 메모리를 낭비할 수 있습니다.

## 연산 복잡도 전체 그림

### 선형 구조

| 연산 | 배열/리스트 | 연결 리스트 | 스택 | 큐 | 덱 |
|------|-----------|-----------|------|-----|-----|
| 인덱스 접근 | **O(1)** | O(n) | -- | -- | O(n) |
| 앞에 삽입 | O(n) | **O(1)** | -- | -- | **O(1)** |
| 뒤에 삽입 | O(1)* | O(1)** | **O(1)** | **O(1)** | **O(1)** |
| 앞에서 삭제 | O(n) | **O(1)** | -- | **O(1)** | **O(1)** |
| 뒤에서 삭제 | O(1) | O(n)*** | **O(1)** | -- | **O(1)** |

### 연관 구조

| 연산 | 해시 테이블 | BST (균형) | 트라이 | 정렬 배열 |
|------|-----------|-----------|--------|----------|
| 삽입 | **O(1)** | O(log n) | O(m) | O(n) |
| 삭제 | **O(1)** | O(log n) | O(m) | O(n) |
| 탐색 | **O(1)** | O(log n) | O(m) | O(log n) |
| 최소/최대 | O(n) | **O(log n)** | -- | **O(1)** |
| 범위 쿼리 | O(n) | **O(log n + k)** | -- | O(log n + k) |
| 접두사 탐색 | O(n) | O(n) | **O(m)** | O(log n + k) |

## 의사결정 프레임워크

### 핵심 질문

| 질문 | 예 | 아니오 |
|------|-----|-------|
| 인덱스로 임의 접근이 필요한가? | 배열/리스트 | 연결 구조 고려 |
| 양쪽 끝에서 빠른 삽입/삭제? | 덱 | 배열이 충분할 수 있음 |
| 키-값 연관이 필요한가? | dict/해시 테이블 | -- |
| 정렬 순서가 필요한가? | BST, 정렬 배열, 힙 | 해시 테이블이 적합 |
| 빠른 최소/최대? | 힙 | -- |
| 접두사 매칭이 필요한가? | 트라이 | -- |
| LIFO 접근이 필요한가? | 스택 | -- |
| FIFO 접근이 필요한가? | 큐/덱 | -- |

## 일반적인 문제 패턴

| 패턴 | 최적 자료구조 |
|------|-------------|
| 빈도 카운팅 | `Counter` |
| 중복 제거 | `set` 또는 `dict.fromkeys()` |
| 상위-K 요소 | 힙 (`heapq`) |
| 범위 쿼리 | BST 또는 `bisect` + 정렬 배열 |
| 그래프/네트워크 | 인접 리스트 (`dict` of `list`) |
| 실행 취소/다시 실행 | 두 개의 스택 |
| 우선순위 작업 처리 | 힙 기반 우선순위 큐 |
| 자동완성/접두사 탐색 | 트라이 |
| 슬라이딩 윈도우 통계 | 단조 덱 또는 두 개의 힙 |

## 흔한 실수

### 실수 1: 리스트를 큐로 사용

```python
# 나쁨: O(n) dequeue
queue = [1, 2, 3]
queue.pop(0)  # 모든 요소를 이동

# 좋음: O(1) dequeue
from collections import deque
queue = deque([1, 2, 3])
queue.popleft()
```

### 실수 2: 루프 안에서 선형 탐색

```python
# 나쁨: O(n*m)
for query in queries:
    if query in large_list:  # 매번 O(n)
        process(query)

# 좋음: O(n+m)
lookup = set(large_list)
for query in queries:
    if query in lookup:  # 매번 O(1)
        process(query)
```

### 실수 3: 내장 자료구조 무시

| 필요 | 사용 | 사용하지 않음 |
|------|------|-------------|
| 스택 | `list` 또는 `deque` | 사용자 정의 연결 스택 |
| 큐 | `deque` | 사용자 정의 구현 |
| 우선순위 큐 | `heapq` | 사용자 정의 힙 |
| 해시 맵 | `dict` | 사용자 정의 해시 테이블 |
| 카운팅 | `Counter` | 수동 dict 카운팅 |

## 실세계 매핑

| 실세계 문제 | 자료구조 |
|-----------|----------|
| 브라우저 히스토리 (뒤로/앞으로) | 두 개의 스택 |
| 인쇄 큐 | 큐 |
| 자동완성 검색바 | 트라이 |
| 데이터베이스 인덱스 | B-트리 / B+ 트리 |
| 소셜 네트워크 친구 | 그래프 (인접 리스트) |
| 리더보드 / 순위 | 힙 또는 균형 BST |
| 맞춤법 검사기 | 해시 집합 + 편집 거리 |
| 파일 시스템 | 트리 (n-ary) |
| CPU 작업 스케줄러 | 우선순위 큐 (힙) |
| 캐시 (LRU/LFU) | 해시 맵 + 이중 연결 리스트 |
| 텍스트 편집기 실행 취소 | 스택 |
| 버전 관리 | DAG (방향 비순환 그래프) |

## 요약

| 개념 | 핵심 요점 |
|------|----------|
| 보편적 최선은 없음 | 각 구조는 특정 연산에 뛰어남 |
| 연산을 파악하라 | 사용 사례에서 어떤 연산이 지배적인지 파악 |
| 전처리 | 반복 쿼리를 위해 인덱스 구축 (해시, 정렬, 트라이) |
| Python 내장 | `dict`, `set`, `deque`, `heapq`, `bisect`, `Counter` |
| 일반적인 패턴 | 카운팅, 중복 제거, 상위-K, 슬라이딩 윈도우, 그래프 |
| 트레이드오프 | 시간 vs 공간, 구축 비용 vs 쿼리 비용 |
| 실세계 매핑 | 문제 구조를 자료구조에 매칭 |
